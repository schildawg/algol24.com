Algol*24

A retro-modern language: classic Pascal syntax over unbounded integers, full Unicode, gradual types, closures, extension functions, bitwise operators and a foreign function interface. The compiler is written in Algol-24 and compiles itself — and so are the bytecode machine that runs it and the library that comes with it.

Install

Two formulae, three platforms.

$ brew tap {{TAP}}
$ brew trust {{TAP}}
$ brew install algol24-vm
$ algvm --version
algvm {{RELEASE}}

The middle line is required rather than advisory: Homebrew will not load a formula from a third-party tap until you have said that you trust it.

That is the machine with the library beside it, installed where a uses looks — so a program says uses graph; by name and the installed unit answers, with no path written in the program and a unit of your own beside it still winning. It is what most people want, and it is the main release.

The compiler is a second formula, and the two coexist. Install it when you want C out of the language, or a binary with no runtime to carry:

$ brew install algol24
$ algc --version
algc {{RELEASE}}

Bottled for arm64_sequoia, arm64_tahoe and x86_64_linux. Anywhere else Homebrew builds from source, which needs a C compiler and takes seconds. The specification is installed beside either one.

Windows is a release download rather than a formula, since Homebrew is not a channel there: unzip it anywhere and run algvm.bat. Foreign calls work — an external reaches a DLL through the same declaration a Unix uses.

The build

It compiles itself.

What is checked in is the compiler's own output. bootstrap/ holds the C that Algol-24 emitted when it last compiled itself, so building needs a C compiler and nothing else — no toolchain, no package manager, no bootstrap binary to trust.

// two stages: the seed builds with cc, then compiles the real thing
$ ./bootstrap/build.sh
$ algc --compile --out=build hello.a24
$ cc -std=c11 -O2 -o hello build/*.c

The build then diffs stage two's output against the checked-in seed. They must be identical. A difference means the seed is stale, which is exactly what you expect after editing the compiler — and --reseed is how you say so deliberately rather than by accident.

The language

Types are optional, and checked when written.

An unannotated name is Any, compatible with everything in both directions. Writing no type is never itself an error, and adding one can only add checking — so annotating more is always safe.

var Name := 'Ada';              // inferred
var Count : Integer := 0;       // declared
const Limit := 100;             // cannot be reassigned

function Add (A : Integer, B : Integer) : Integer;
begin
    Exit A + B;
end

Semicolons terminate rather than separate, so the one before end is required. Exit returns; there is no return. Functions are values, they nest, and they close over what they see.

The capability

Classic on the surface, not underneath.

An Integer is unbounded: arithmetic past the machine width grows rather than wrapping or raising, and demotes again the moment a result fits. There is no build switch. Source, identifiers and text are Unicode throughout, and text is measured in characters rather than bytes — so Length ('你好') is 2.

class Point;
var
    X : Integer;
    Y : Integer;

begin
    operator + (Other : Point) : Point;
    begin
        Exit Point (X + Other.X, Y + Other.Y);
    end
end

Classes with operators a program may define, closures and nested subprograms, exceptions, enumerations, five collections, modules including circular ones, and a foreign function interface that reaches C — so a program can call SDL or libm directly. The examples draw a pie chart and the word hello in five scripts, with color emoji, into an SDL2 window.

The bits of an Integer are reached with &, |, ^, ~, << and >>, and every Integer is two's complement extended infinitely to the left — so every operation is total and no width is named anywhere. A left shift grows rather than wrapping, and a right shift floors where div truncates.

WriteLn (6 & 3);        // 2
WriteLn (~0);           // -1, every bit set
WriteLn (-1 & 5);       // 5, all ones selects everything
WriteLn (1 << 70);      // 1180591620717411303424

A routine obliged to pick a width instead is correct for the values that fit it and silently wrong for the rest, with nothing in its declaration able to say which — which is why these are operators rather than a library's business. A class may define the five binary ones and unary ~ for its own instances, and and, or and not are untouched: they test truthiness and short-circuit, and writing one where a bitwise operator was meant now raises a [WARN].

The extension

Free functions that read like methods.

A top-level subprogram marked extension may also be called with method syntax on its first parameter: Trim (S) and S.Trim () are one call, and a unit of free functions composes left to right — Line.Trimmed ().Shortened (12).Upper ().

extension function Shortened (S : String, To : Integer) : String;
begin
    if Length (S) <= To then Exit S;

    Exit Copy (S, 0, To) + '...';
end

WriteLn (Shortened (Title, 4));   // both spellings
WriteLn (Title.Shortened (4));      // are one call

A member of the name always wins, so no call that compiles today can change meaning — and where a member does hide an extension you can see, a [WARN] names the class that took it. What a value responds to is decided by the calling file's own uses clauses rather than globally, so a unit that imports Strings for its own use does not hand S.Trim () to its importers. extension is not a keyword either — it is an ordinary identifier recognized by its position, so a program may still name a variable after it.

The language was feature-complete at v0.1.0, and it is stable rather than closed: it changes only on measured demand from a project using it, and the measurement goes in the proposal. This was the first such change, because the library now being written in Algol-24 had measured the alternatives — grow the core one verb at a time, or wrap String in a class whose seam answers 13 for the length of a five-character string — and a unit of functions that composes is neither.

v0.1.6 is three more on the same terms: the bitwise operators above, a precision for Str that renders 2.675 to two places as 2.67 because it rounds from the value rather than from a rendering of it, and Buffer accessors for a four-byte unsigned word and an eight-byte IEEE 754 Double — little-endian whatever the machine is, so a record written on one and read on another agrees.

The machine

Three processors, and they must agree.

algvm is a stack machine for Algol-24, written in Algol-24 and compiled by algc like everything else here. It is a second binary rather than a mode of the compiler: it imports the compiler's own front end, so a program that will not parse fails the same way whichever of the three you reach for. Its opcodes are numbered as Crafting Interpreters numbers them, so the book reads alongside the source.

{{OPCODES}}opcodes, one reference entry each
140tests of the machine itself
276cases it answers like the others

This page is the evidence, and the check runs on every push. The generator that builds it is 2,250 lines of Algol-24 reading 27,000 lines of Markdown; run it under each processor in turn and the bytes that come out do not move.

$ ./build.sh                    # the compiled generator, 0.16s
$ mv site site-cc && mkdir site
$ algvm gen/Main.a24            # the machine, 4.06s
$ diff -r site-cc site          # and it prints nothing

It also hosts the compiler: run algc on the machine and ask it for C, and the C is byte-identical to what a native algc emits — the whole front end and the whole back end, running as bytecode, agreeing to the byte.

The tree-walking interpreter is the slow one — 42.1s for the same four pages, having gained a collector of its own in v0.2.4 — and it agrees to the byte as well. A disagreement would be a bug in whichever processor is the odd one out, and that is most of what building a third one was for.

Collection is precise rather than a guess. The compiler emits the addresses of a program's module-level variables and a shadow stack for its locals, so nothing has to ask whether a word might be a pointer. All three processors collect without being asked now — the machine from the start, the tree-walker since v0.2.4, and compiled code since v0.2.6, which also made text collectable at all: a String used to come from an arena that never freed, so every Str and every + was held for the life of the process.

Building this site is the measurement. Peak memory fell from 84 MB to 36 MB compiled and from 321 MB to 66 MB on the machine, for about 15% more time on the machine and none measurable anywhere else. It is easy to misremember any of this as a feature of the machine, and it is not.

A runtime error now says where it happened, file and line, under the interpreter and under the machine. Compiled Algol-24 deliberately carries no source positions and will not: storing one before every statement is a cost every program would pay forever so that a failing one could be read. A program that wants that runs on the machine, which can disassemble itself — --list walks every chunk, --trace N keeps the last N instructions with the stack pointer and call depth, and --watch dumps the instant a message is raised. Each processor finds the location its own way, and the machine pays nothing at all until something fails.

The library

What alpha meant.

algol24-library v{{LIBRARY}} is ten units, borrowing Turbo Pascal's names as an homage rather than as a compatibility target. Its version is its own on purpose: the library is a user of the language rather than part of it, with its own repository, its own releases and its own record of what it has found wrong.

graphpixels, shapes, text, windows, viewports
crtthe text console — colors, cursor, keys
stringsthe operations a String wants
maththe numeric functions
randomgenerators and distributions
soundtones and samples
timeclocks, dates, zones
filefiles, directories, paths
dosthe environment, disks, process exec
testingassertions, for programs that test themselves

graph and sound reach SDL2 through the language's own foreign function interface, which is the argument for having one: a library written in the language can go and get what the language does not have.

uses graph;

InitGraph (640, 480, 'algol24.com', False);

var V := ViewPort (0, 0, 640, 480, 1);

SetColor (V, LightCyan);
Circle (V, 320, 240, 180);
Show (V);
10units, each its own file
850tests across them
119reference examples, run not quoted

The examples are the part worth singling out. Every one in the library's reference is run and its output compared against what the entry claims, so an example that stops being true fails a build rather than misleading a reader.

This is also what the project meant by calling itself alpha. What the language lacked was never a feature; it was a library written in Algol-24 rather than bolted into the runtime. It needed exactly one addition to the language to be possible — a uses now finds a unit in an installed library, not only one beside the program — and nearer still wins, so installing a library can never change what an existing program already means by a name.

The guarantee

The specification is the authority.

Where the implementation and the specification disagree, it is the implementation that is wrong. The difference is recorded as a defect and carries a program that reproduces it.

{{RULES}}rules, each claimed by a case
247unit tests in Algol-24
279cases in the corpus

Every case runs interpreted and compiled, and every run must be green; the 276 conformance and refusal cases run on the machine as well. A case the interpreter gets right and the compiled program gets wrong is a gap, and a gap is a failure rather than a note. A defect's test is stranger still: it records the wrong behavior and passes for as long as that behavior lasts, turning red the day the defect is fixed.

None of which finds the bugs that a program finds. v0.2.4 is sixteen defects, and not one of them was found by reading the compiler: every report came from a game of about twenty units, or from this website — both written in Algol-24 by people meeting the language as users of it. Five of the sixteen turned out to be one bug, and its worst shape read a program-level variable as an imported enumeration's member, so every assignment to it was discarded in silence. A seventeenth was found while fixing the others, which nobody reported.

$ ./defects.sh
0 reproducing, 16 fixed, of 16 checked

That harness is new, and it is the only one here written to fail: each report is reduced to the smallest program that shows it and run under whichever processors disagree, so the sweep goes green only when every one is fixed and stays green only while they remain so.

Then there is the compiler itself. It compiles itself, compiles itself again with the result, and the two emissions must be byte-identical. That is a determinism check as much as a correctness one — no hash-order iteration, no timestamps, no pointer values may reach the emitted text. A compiler can be entirely correct and still fail it, and nothing else would notice.

$ ./fixedpoint.sh
generation 3 is identical to generation 2

The name

Why Algol, and why 24.

Algol-24 is not a successor to ALGOL 60. It is its own language, and a modern one. The name is for the lineage that runs through Pascal, and because the two look strikingly alike on the page.

The 24 is a vintage, not a version. It marks 2024, when the work started. There will be no Algol-26.

Algol is also a star — β Persei, the Demon Star, an eclipsing binary whose two components pass in front of one another every 2.87 days. Two bodies that have to be observed together, whose agreement over time is the whole measurement. For a language with an interpreter and a compiler that are required to agree, the name turned out to be doing more work than it was given.

Provenance

It began as Lox.

Algol-24 descends from Bob Nystrom's Lox, from Crafting Interpreters — a debt that is still visible in the architecture, in the Scanner → Parser → Resolver → Interpreter pipeline, and in the empty vm/ directory waiting for the bytecode machine from the book's third part. The syntax became Pascal's because Pascal was the first language its author loved. Everything since has been the features worth keeping from forty years of using other people's.
