# algol24.com

The home of [Algol-24](https://github.com/schildawg/algol24), generated by a
program **written in Algol-24 and compiled by `algc`**.

That is not a stunt. The compiler is written in the language it compiles and
checks that it reproduces its own output byte for byte; the site inherits the
same habits, down to the generator preserving a file's final newline because
losing it would be a one-byte difference between input and output.

```sh
./build.sh          # -> site/
```

## Layout

| Where | What |
|---|---|
| `gen/` | the generator, in Algol-24 |
| `templates/` | page templates, with `{{PLACEHOLDER}}` substitution |
| `static/` | anything copied through untouched |
| `brand/` | logo masters, the palette, and the icon build — see `brand/BRAND.md` |
| `prototype/` | the hand-written design reference the generator must reproduce |
| `vendor/algol24` | the compiler, as a submodule. Supplies both `algc` and the docs |
| `site/` | the output. Generated; not checked in |

## The compiler is a submodule, and does two jobs

`vendor/algol24` is pinned, and CI checks it out for both reasons at once: its
`bootstrap/` builds `algc`, and its `ALGOL-24.md` and `README.md` are the source
of the Reference and Tour pages. One checkout, one pinned commit, no way for the
documentation on the site to drift from the compiler that built it.

Updating the site to a newer compiler is therefore a deliberate act:

```sh
git -C vendor/algol24 pull origin main
git add vendor/algol24 && git commit -m 'site: track algol24 <sha>'
```

## Status

⚠️ **The generator is a stub.** It renders one page from one template, which is
enough to prove the pipeline end to end — `cc` builds the seed, the seed builds
`algc`, `algc` compiles the generator, the generator writes the site, CI
publishes it. That whole chain works today.

What it does not do yet is parse Markdown or highlight Algol-24, which is what
turns `ALGOL-24.md` into the Reference. Both are blocked on the language rather
than on this repository:

- **a string library** — `Trim`, `Split`, `Replace`, `StartsWith`, `LowerCase`,
  and a `Pos` that takes a start offset;
- **`MkDir`** — the output tree is decided by the content, so no script can
  create it in advance.

Both are written up in `WISHLIST-SITEGEN.md` in the compiler repository, in the
format of its own `WISHLIST.md`.

## Deployment

GitHub Actions builds and publishes to GitHub Pages on every push to `main`.

The custom domain is a separate, deliberate step: add `algol24.com` under
**Settings → Pages**, point the DNS at GitHub, and drop a `CNAME` file into
`static/`. Until then the site publishes to the default `github.io` address and
`algol24.com` keeps serving WordPress.
